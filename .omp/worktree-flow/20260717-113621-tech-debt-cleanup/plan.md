# Tech Debt Cleanup

## Context
Implement the full set of debt fixes identified in the repository audit: strict configuration and manifest validation, complete Drive retry coverage, enforced CI quality gates, typed engine/report/progress contracts, bounded-memory summary generation with tests, and removal of dead or duplicated scaffolding. Preserve the current backup pipeline and external report JSON while making boundary failures explicit, transient Drive failures retryable, and maintenance checks reproducible.

## Approach

### 1. Make local state inputs strict before any remote work
- In `src/drive_backup/config.py`, replace the `Config.__dataclass_fields__` filtering in `load_config()` with an explicit validator that requires the YAML root to be a mapping, rejects sorted unknown keys with `ValueError("Unknown configuration keys: <keys>")`, and normalizes accepted values before constructing `Config`.
- Validate all string fields (`backup_root`, `profile_name`, `drive_parent_folder_name`, `manifest_path`, `credentials_path`, `token_path`), all list fields (`exclude_dirs`, `exclude_files`, `exclude_path_patterns`, `exclude_specific_files`, `no_size_limit`) as lists of strings, `exclude_symlinks` as exactly `bool`, `max_retries` as an integer excluding `bool`, numeric megabyte/rate fields as finite `int | float` excluding `bool` and normalize them to `float`, and `size_limits_by_type` as `str -> finite int | float` normalized to `float`. Retain the existing non-negative/range checks in `Config.__post_init__`; type errors identify the field as `Invalid configuration value for '<field>': <expectation>`.
- In `src/drive_backup/dedup.py`, add `class ManifestLoadError(RuntimeError)` and make `Manifest.load(path: str) -> Manifest` return empty only when the file is absent. Existing files must decode to a mapping with exact integer `version == 1`, a mapping-valued `files`, string relative-path keys, and entries containing exactly the six `ManifestEntry` fields with `md5`, Drive IDs, and `last_uploaded` as strings; `size` as a non-negative integer excluding `bool`; and `mtime` as a finite number excluding `bool`, normalized to `float`. JSON, I/O, schema-version, and entry-validation failures raise `ManifestLoadError("Could not load manifest from <path>: <reason>")`; do not skip malformed entries or silently rebuild.
- Keep `BackupEngine.run()` loading the manifest before `DriveAPI.authenticate()`, preserving the fail-before-Drive-side-effects invariant. Catch `ManifestLoadError` around `engine.run()` in `src/drive_backup/cli.py`, print `[red]Backup failed:[/] <message>`, and raise `SystemExit(1)` from it so CLI users receive a concise failure rather than a traceback.
- Flip the two tolerance tests in `tests/test_dedup.py` (`TestManifestCorrupted::test_load_corrupted_json` and `test_load_malformed_entry`) to assert `pytest.raises(ManifestLoadError)`; also replace their `tempfile.NamedTemporaryFile(delete=False)` + `os.unlink` pattern with `tmp_path`. Keep `test_load_ignores_corrupted_sibling_temp_file` passing unchanged — a stray sibling temp file must not affect a valid manifest. `Manifest.load` callsites are exactly `src/drive_backup/engine.py:76` plus the test files listed by `grep -rn "Manifest\.load" tests`; only the two tolerance tests change behavior.

### 2. Put every Drive API request behind the existing retry policy
- Generalize `DriveAPI._execute_with_retry` in `src/drive_backup/drive_api.py` to `def _execute_with_retry(self, fn: Callable[[], T]) -> T` using a module `TypeVar("T")`; retain retryable statuses `(429, 500, 503)`, exponential backoff plus jitter, `max_retries` semantics, and immediate propagation of other statuses.
- Route folder list/create in `get_or_create_folder()` and file list in `find_file_by_name_and_parent()` through `_execute_with_retry`, in addition to the already wrapped upload/update/trash operations. Apply `RateLimiter.wait()` immediately before each write attempt, including retried folder creation; reads remain unthrottled. OAuth credential loading/refresh and service construction stay outside this policy because they are not Drive file requests.
- Preserve folder caching and response shapes. A failed lookup/create must not populate `_folder_cache`; a successful retry populates it once.

### 3. Replace string and `Any` contracts without changing JSON or CLI behavior
- In `src/drive_backup/report.py`, define exported `TypedDict`s `SkippedFileRow`, `UploadedFileRow`, `ErrorFileRow`, `PrunedFileRow`, `PruneErrorRow`, and `ExtensionBreakdownRow` with exactly the keys each list-comprehension currently emits (lines 164-210), plus an exported `BackupReport` containing every key currently returned by `generate_report()`. Change signatures to `generate_report(stats: BackupStats) -> BackupReport`, `_extension_breakdown(...) -> list[ExtensionBreakdownRow]`, and `save_report(report: BackupReport, path: str) -> None`; preserve every current key, value type, ordering, and serialized JSON shape.
- In `src/drive_backup/engine.py`, add `class ProgressKind(StrEnum)` with exact values `\"skipped\"`, `\"dedup\"`, `\"would_upload\"`, `\"uploaded\"`, and `\"error\"`, plus `@dataclass(frozen=True, slots=True) class ProgressEvent` with `kind: ProgressKind` and `reason: str = \"\"`. Change `BackupEngine.run` and `_process_file` callbacks to `Callable[[FileEntry, ProgressEvent], None] | None` and return `BackupReport`; emit the same reason strings in `ProgressEvent.reason` instead of colon-encoding them.
- Update the sole production callback in `src/drive_backup/cli.py` to branch on `event.kind`, preserving verbose labels and skipped-file output. Change `_print_summary(console: Console, report: BackupReport, *, verbose: bool = False) -> None`; remove report-related `Any` imports and the `type: ignore` indexing suppressions in `tests/test_report.py`. Update all callback/report fakes in `tests/test_cli.py` (including the `"would_upload:test.txt"` fake at line 105) and the callback assertion in `tests/test_engine.py:75` (`any("would_upload" in action ...)`) to match on `ProgressEvent.kind`/`reason`; no string compatibility shim remains.

### 4. Make profile summaries bounded by aggregate cardinality, not file count
- In `scripts/generate_summary.py`, replace the `eligible`, `skipped`, and `errors` `FileEntry` collections in `generate_summary()` with a `SummaryStats` dataclass: counts/sizes, folder and extension aggregates, skip-reason aggregates, a 25-item eligible min-heap, a 10-item skipped min-heap, and an error count. Store error markdown during scanning in `tempfile.SpooledTemporaryFile(mode=\"w+\", max_size=1_048_576, encoding=\"utf-8\")` so large error sets spill to the system temp directory.
- Extract `_collect_summary(config: Config, error_output: TextIO) -> SummaryStats` and `_write_summary(output: TextIO, config: Config, stats: SummaryStats, error_input: TextIO, report_date: date) -> None`; no existing equivalent exists. `_write_summary` seeks the error stream and writes the current Markdown sections and wording in the current order without first constructing one giant string. `generate_summary(config_path, out_dir)` remains the public entry point and returns the existing `SummaryResult`.
- Use `(size, relative_path, reason)` tuples for deterministic heap ties, sort only the bounded heaps and aggregate maps for rendering, retain all error lines via the spool, and keep empty scans, zero-byte totals, path shortening, output filename, and percentage formatting unchanged.
- Add `tests/test_generate_summary.py` covering aggregate/render output, deterministic top-25/top-10 truncation, empty scans, and more than 1 MiB of error lines spilling while all errors remain in the report. Tests call `_collect_summary`/`_write_summary` with `StringIO` or a deliberately small `SpooledTemporaryFile`; they do not scan a real user profile.

### 5. Enforce checks and remove proven scaffolding debt
- Add `.github/workflows/quality.yml` on pushes and pull requests. An Ubuntu `quality` job uses `actions/checkout@v4`, `actions/setup-python@v5` with Python `3.11` and pip caching, installs `-e \".[dev]\"`, then runs `ruff check .`, `mypy src tests scripts`, `black --check src tests scripts`, and `pytest`. A separate `windows-tests` job uses `windows-latest`, the same checkout/setup/install, and runs `pytest` to exercise the Windows-focused package on its minimum Python.
- Delete unused `scanner._truncate_relative_path()` and its three direct tests/import in `tests/test_scanner.py`; retain the active `\\\\?\\` long-path I/O handling in `scan()` and `BackupEngine._local_path_for_manifest_key()`.
- Add `tests/file_helpers.py` with `write_tree(root: Path, files: Mapping[str, str | bytes]) -> None`, replacing the duplicated `_make_tree` methods in `tests/test_engine.py` and `tests/test_scanner.py`. Convert `TemporaryDirectory()`/`mkdtemp()` usage in `tests/test_engine.py`, `tests/test_scanner.py`, and `tests/test_dedup.py` to pytest `tmp_path` so all state is scoped and cleaned; keep behavior assertions and Drive fakes local where their behavior differs.

## Critical files & anchors
- `src/drive_backup/config.py` — `load_config()` (lines 205-220): the only place YAML enters the dataclass; strict key/type validation lives here.
- `src/drive_backup/dedup.py` — `Manifest.load()` (lines 69-91): currently swallows corrupt JSON and malformed entries; becomes the fail-closed boundary with `ManifestLoadError`.
- `src/drive_backup/drive_api.py` — `_execute_with_retry` (lines 257-276) vs. direct `.execute()` calls in `get_or_create_folder` (102-134) and `find_file_by_name_and_parent` (143-167): the retry-coverage gap to close.
- `src/drive_backup/engine.py` — `_process_file` (172-246): emits the colon-encoded progress strings (`"skipped"`, `"dedup:..."`, `"would_upload:..."`, `"uploaded:..."`, `"error"`) that become `ProgressEvent`.
- `scripts/generate_summary.py` — `generate_summary()` (348-540): the unbounded `eligible`/`skipped`/`errors` lists to replace with `SummaryStats` + spooled error output.

## Verification
All commands run from the repository root after `pip install -e ".[dev]"`.

1. Config strictness (new behavior): `pytest tests/test_config.py -q` passes with new cases proving `load_config()` raises `ValueError` for an unknown key (e.g. `exclude_file: ["x"]`) and for a wrong-typed value (e.g. `exclude_dirs: "venv"`), while `config.example.yaml` still loads successfully — run `python -c "from drive_backup.config import load_config; load_config('config.example.yaml')"` and expect exit 0.
2. Manifest fail-closed (new behavior): `pytest tests/test_dedup.py -q` passes with the flipped corruption tests; manually, a manifest containing `"version": 2` must raise `ManifestLoadError` naming the path, and a missing manifest file must still return an empty manifest.
3. Drive retry coverage (new behavior): `pytest tests/test_drive_api.py -q` passes with a fake service whose first `files().list().execute()` raises a retryable `HttpError` (status 503) and whose second succeeds — assert `get_or_create_folder` returns the folder id, the cache is populated once, and a non-retryable status (e.g. 404) raises immediately without a second call.
4. Typed contracts: `pytest tests/test_engine.py tests/test_cli.py tests/test_report.py -q` passes with `ProgressEvent`-based callbacks; `mypy src tests scripts` passes with zero `type: ignore` left in `tests/test_report.py` and no report `Any` in `cli.py`/`engine.py`; report JSON keys are byte-identical to the pre-change shape — snapshot `generate_report(BackupStats(...)).keys()` in one existing test.
5. Bounded summary (new behavior): `pytest tests/test_generate_summary.py -q` passes, including the >1 MiB error-spool case; with a temporary `config.yaml` pointing `backup_root` at a small fixture tree, `python scripts/generate_summary.py --out <tmpdir>` (the script reads `config.yaml` from the cwd; `--out` is the only output flag) produces a `profile-summary-<date>.md` with the same section headings and ordering as before.
6. Full gates: `pytest`, `ruff check .`, `mypy src tests scripts`, `black --check src tests scripts` all pass; `grep -rn "_truncate_relative_path" src tests` returns nothing; the new `.github/workflows/quality.yml` parses (GitHub validates on push).

## Assumptions & contingencies
- User-approved decisions: implement the full cleanup list, and fail closed on malformed or unsupported manifests before any Drive side effect.
- Existing valid `config.yaml` files and version-1 manifests remain compatible; no migration or compatibility alias is introduced.
- CI targets the package minimum, Python 3.11, because `pyproject.toml` declares `requires-python = ">=3.11"`. If GitHub Actions no longer offers Python 3.11 during implementation, use the oldest available 3.x runner and keep mypy/Ruff/Black configured for Python 3.11.
