# Machine State Snapshots

## Context
Extend `drive-backup` beyond ordinary profile files by generating restore-oriented machine-state inventories under the configured backup root, then letting the existing scanner, deduplication, manifest, upload, and prune pipeline treat those JSON files like the rest of the profile. The first version captures broad, unredacted Windows and WSL diagnostics but does not introduce a second file-copy mechanism for configuration or credential files; ordinary files already under `backup_root` remain the existing pipeline's responsibility. Snapshot refresh is default-on, `--skip-machine-state` suppresses only the refresh, and a failed collector warns but never prevents the remaining collectors or ordinary backup.
## Approach

### 1. Add the durable snapshot and configuration primitives

1. Promote the same-directory atomic JSON algorithm currently private as `src/drive_backup/dedup.py::_atomic_write_json` into `src/drive_backup/utils.py` with the exact shared signature `atomic_write_json(path: str | Path, data: object) -> None`. Preserve parent creation, a UTF-8 `NamedTemporaryFile` in the destination directory, `json.dump(..., indent=2)`, `flush`, `os.fsync`, atomic `os.replace`, and best-effort temporary-file cleanup; migrate `Manifest.save()` to the new symbol and delete the private duplicate rather than retaining an alias.
2. In `src/drive_backup/config.py`, define the ordered tuple `MACHINE_STATE_COLLECTORS = ("system", "windows_apps", "package_managers", "developer_tools", "windows_features", "services", "scheduled_tasks", "drivers", "network", "environment", "wsl")` and add `Config.machine_state_collectors: list[str]` whose default is a fresh list in that order. Register it as a string-list YAML field, then reject unknown names and duplicates with a `ValueError` that names the invalid entries and valid collector names; preserve user order because it is execution/report order. An empty list is valid and produces only snapshot metadata. Add the same key and names to `config.example.yaml`; do not add a configurable output path or enable boolean because the selected location and default-on CLI contract are fixed.
3. Reserve the generated directory `<backup_root>/_machine_state/`. Use stable filenames `system.json`, `windows_apps.json`, `package_managers.json`, `developer_tools.json`, `windows_features.json`, `services.json`, `scheduled_tasks.json`, `drivers.json`, `network.json`, `environment.json`, `wsl.json`, and `snapshot.json`. Do not special-case scanner exclusions: these files intentionally obey the same configured directory, path, filename, and size rules as ordinary backup files; the shipped defaults do not exclude `_machine_state` or JSON.

### 2. Implement isolated Windows and WSL collectors

1. Add `src/drive_backup/machine_state.py`; no existing product subprocess or inventory abstraction exists. Define:
   - `CollectorStatus(StrEnum)` with exact values `succeeded`, `partial`, and `failed`.
   - `CollectorOutcome` as a frozen, slotted dataclass with `name: str`, `status: CollectorStatus`, `output_file: str | None`, `warnings: tuple[str, ...]`, and `previous_output_retained: bool`; `output_file` is always a forward-slash path relative to `backup_root`, such as `_machine_state/system.json`.
   - A typed `CommandRunner` protocol accepting `argv: Sequence[str]` and keyword-only `timeout: float`, returning `subprocess.CompletedProcess[str]`.
   - `run_command(argv: Sequence[str], *, timeout: float) -> subprocess.CompletedProcess[str]`, using `subprocess.run` with an argument vector, `shell=False`, `stdin=DEVNULL`, captured output, `text=True`, UTF-8 decoding with replacement, and no exception on a nonzero exit.
   - `collect_machine_state(backup_root: str, collector_names: Sequence[str], *, runner: CommandRunner = run_command) -> list[CollectorOutcome]`.
   - `run_resolved_tool(executable: str, args: Sequence[str], *, timeout: float, runner: CommandRunner, powershell_executable: str, wrapper_path: str) -> subprocess.CompletedProcess[str]`. Invoke `.exe`/`.com` directly. For `.ps1`/`.cmd`/`.bat` shims, invoke a collector-owned fixed PowerShell wrapper via `[powershell_executable, "-NoLogo", "-NoProfile", "-NonInteractive", "-File", wrapper_path, executable, *args]`; the wrapper is exactly `param([Parameter(Position=0,Mandatory=$true)][string]$Executable,[Parameter(ValueFromRemainingArguments=$true)][string[]]$ToolArgs) & $Executable @ToolArgs; exit $LASTEXITCODE`. Create the wrapper once with a `.ps1` suffix, delete it in `finally`, and pass the executable/arguments as process argv—not command source. Never use `cmd.exe /c` or `subprocess.list2cmdline`, whose C-runtime quoting does not escape cmd metacharacters.
2. Resolve `powershell.exe`, `wsl.exe`, and optional package/developer tools with `shutil.which`; never interpolate a discovered executable, distro name, path, or output into PowerShell/sh source. PowerShell invocations use `[powershell.exe, "-NoLogo", "-NoProfile", "-NonInteractive", "-Command", FIXED_SCRIPT]`, set console output encoding to UTF-8 in the fixed script, and emit `ConvertTo-Json -Depth 12`. WSL invocations pass each distro through the separate `--distribution`, `<name>`, `--exec` arguments; fixed `sh -lc` scripts contain no user text. Use a 120-second timeout for ordinary commands and 300 seconds for Winget export and each WSL distribution. Status aggregation is exact: `succeeded` means every command that was present and invoked succeeded (an absent optional executable is recorded as `available: false` and does not downgrade status); `partial` means at least one payload component succeeded and at least one invoked command/distro failed; `failed` means no current payload could be produced. A missing required `powershell.exe`, timeout, nonzero exit, invalid JSON, or write failure becomes a warning on that collector, not an exception escaping the collector boundary.
3. Every successful collector writes one stable file atomically with this envelope: `{"schema_version": 1, "collector": "<name>", "collected_at": "<UTC ISO-8601 Z>", "data": <collector payload>}`. Outputs are intentionally unredacted: retain environment values, IP/MAC/DNS data, service paths/accounts, scheduled-task actions/arguments, package sources, serial numbers, usernames, domains, Git configuration output, and command stdout/stderr. Do not copy arbitrary configuration/credential file contents; this feature remains inventory-only. Keep raw subprocess errors in collector warnings because the user explicitly chose full diagnostics.
4. Implement the exact collector payloads:
   - `system`: one PowerShell object containing full `Get-ComputerInfo`, `Get-Culture`, `Get-UICulture`, and `Get-TimeZone` results.
   - `windows_apps`: desktop application entries from HKLM/HKCU 32-bit and 64-bit `...\CurrentVersion\Uninstall\*` keys with all returned registry properties, plus full current-user `Get-AppxPackage` results.
   - `package_managers`: Winget's native export JSON generated via a collector-owned temporary file with argv `winget export --output <temp_path> --include-versions --accept-source-agreements --disable-interactivity`, Chocolatey output (`choco list --local-only --limit-output`, falling back to `choco list --limit-output` only when the first syntax exits nonzero), and Scoop output from `scoop export`. Store each tool as `{"available": bool, "returncode": int | null, "stdout": str, "stderr": str, "data": object | null}`; Winget's validated export JSON occupies `data`, while Chocolatey/Scoop retain raw stdout. Always remove Winget's temporary export in `finally`. Resolve tools independently; absence is a successful inventory fact, while a failed available tool makes the collector `partial` if another payload exists.
   - `developer_tools`: full `Get-Module -ListAvailable` results and command inventories for VS Code extensions (`code --list-extensions --show-versions`), global npm packages (`npm list --global --depth=0 --json`), pipx (`pipx list --json`), Cargo-installed crates (`cargo install --list`), global .NET tools (`dotnet tool list --global`), user Python packages (`python -m pip list --user --format=json`), and global Git configuration with origins (`git config --global --list --show-origin`). Store every tool under the same `available`/`returncode`/`stdout`/`stderr`/`data` command-result shape, parsing JSON-capable commands into `data` and retaining raw output regardless. Resolve each optional command independently; absence does not downgrade status, while a failed available tool yields `partial` when another component succeeded.
   - `windows_features`: full `Get-WindowsOptionalFeature -Online` and `Get-WindowsCapability -Online` results. If either command requires elevation or fails, retain the other's result and mark the collector `partial`.
   - `services`: full `Get-CimInstance Win32_Service` results, including `PathName`, `StartName`, state, and start mode.
   - `scheduled_tasks`: full `Get-ScheduledTask` results, including principals, triggers, settings, and actions, serialized to depth 12.
   - `drivers`: full `Get-CimInstance Win32_PnPSignedDriver` results.
   - `network`: full results from `Get-NetAdapter`, `Get-NetIPConfiguration -Detailed`, `Get-NetRoute`, `Get-DnsClientServerAddress`, and `Get-NetFirewallProfile`, plus raw `netsh wlan show interfaces` and `netsh wlan show profiles` output. Do not request Wi-Fi cleartext keys because that would be credential extraction rather than an inventory.
   - `environment`: complete Process, User, and Machine dictionaries from `[Environment]::GetEnvironmentVariables(...)`, with values unchanged.
   - `wsl`: enumerate names with a fixed PowerShell wrapper around `wsl.exe --list --quiet` so Windows PowerShell handles WSL's Windows output encoding, and also retain raw `wsl.exe --list --verbose` output. The payload is `{"available": bool, "distribution_list_verbose": str, "distributions": [...]}`; each distro row has `name` and a `commands` mapping whose values use the same `available`/`returncode`/`stdout`/`stderr` shape. Inspect every registered distro, including stopped distros. Use exact command keys/argv: `os_release` = `cat /etc/os-release`; `uname` = `uname -a`; `environment` = `env`; `mounts` = `mount`; `enabled_systemd_units` = `systemctl list-unit-files --state=enabled --no-pager` when `systemctl` exists; package-manager detection uses fixed `command -v` probes and then the first available pair among `dpkg-query -W -f=${binary:Package}\t${Version}\t${Architecture}\n` plus `apt-mark showmanual`, `rpm -qa --qf %{NAME}\t%{VERSION}-%{RELEASE}\t%{ARCH}\n`, `apk info -vv`, or `pacman -Q` plus `pacman -Qqe`; optional inventories are `snap list`, `flatpak list`, `npm list --global --depth=0 --json`, `pipx list --json`, `cargo install --list`, and `dotnet tool list --global`. Pass distro names only as argv values. A failed distro records its own warning and does not stop later distros; the top-level collector is `partial` when any registered distro fails.
5. Before running enabled collectors, remove stable output files belonging to known but disabled collector names so a later `--prune` can remove them from Drive. Never perform this reconciliation when `--skip-machine-state` suppresses the entire refresh. A deletion error leaves the file in place, is logged with `logger.warning`, and is added to top-level `snapshot.json` `reconciliation_warnings`; it does not abort collection. For an enabled collector, atomically replace its prior file only after successful payload construction; on `partial`, write the available payload and warnings; on `failed`, retain the prior file if it exists and set `previous_output_retained=true`.
6. After all collectors finish, atomically replace `snapshot.json` with `schema_version`, UTC `started_at`/`completed_at`, `socket.gethostname()`, configured collector order, `reconciliation_warnings`, and one JSON row per `CollectorOutcome`. Include the retained file's relative path when a failed collector kept an older output. Catch failures around each collector invocation inside `collect_machine_state`; an unexpected exception becomes that collector's `failed` outcome and collection continues. If creating `_machine_state` or writing `snapshot.json` fails, log the error and append a synthetic `CollectorOutcome(name="snapshot", status=failed, output_file=<prior snapshot path or None>, warnings=(<error>,), previous_output_retained=<whether prior snapshot exists>)` instead of aborting the backup.

### 3. Refresh before scan and expose results without changing upload semantics

1. Extend `BackupEngine.__init__` to the exact signature `__init__(self, config: Config, dry_run: bool = False, full: bool = False, prune: bool = False, collect_machine_state_snapshot: bool = True) -> None`. Store the flag and a new empty `self._prune_protected_paths: set[str]`. At the start of `run()`, capture `backup_root_available = os.path.isdir(config.backup_root)` before any refresh. After manifest loading/full-mode handling and before Drive construction/authentication: if collection is enabled and the captured root is available, call `collect_machine_state(config.backup_root, config.machine_state_collectors)`; if collection is enabled but the root was unavailable, do not create it and record a synthetic failed `snapshot` outcome with warning `Backup root is unavailable; machine-state refresh skipped`. Reuse the captured boolean—not a later filesystem check—in the existing prune unavailable-root guard. This preserves the current missing/disconnected-root safety even though collection normally writes before scan.
2. Refresh during `--dry-run` as well as normal runs so the preview reports the files that the next backup would upload; existing dry runs already write local reports. `--dry-run --skip-machine-state` is the no-refresh preview. Skipping refresh leaves prior `_machine_state` files in place, so they remain eligible for ordinary scan/dedup/upload; it does not exclude or delete them.
3. In `src/drive_backup/report.py`, add `MachineStateCollectorRow(TypedDict)` with exact fields `name: str`, `status: str`, `output_file: str | None`, `warnings: list[str]`, and `previous_output_retained: bool`; add `machine_state_refreshed: bool` and `machine_state_collectors: list[MachineStateCollectorRow]` to `BackupStats`/`BackupReport`, and serialize enums/tuples to plain JSON values in `generate_report`. Set `machine_state_refreshed=True` only when `collect_machine_state(...)` was actually called against an available root; leave it false for `--skip-machine-state` and the unavailable-root synthetic failure. Do not count collector warnings as `error_files` or increment `files_skipped_error`; otherwise the existing prune guard would incorrectly suppress pruning.
4. For every `failed` outcome, add its expected generated path (`_machine_state/<collector-name>.json`, or `_machine_state/snapshot.json` for the synthetic metadata outcome) to `self._prune_protected_paths`. Change `_stale_manifest_entries()` to exclude protected keys before `_prune_stale_manifest_entries()` runs. This preserves the last remote copy when an enabled collector failed and no local artifact exists; disabled collectors produce no outcome/protection, so their deleted files remain intentionally pruneable. Do not use the global `files_skipped_error` guard for this path-specific condition.
5. In `src/drive_backup/cli.py`, add only `--skip-machine-state` (`store_true`) with exact help text `Do not refresh generated machine-state inventories before this backup`, and pass `collect_machine_state_snapshot=not args.skip_machine_state` at the sole production `BackupEngine` construction. Do not add per-collector flags or a separate subcommand; persistent collector selection belongs in `machine_state_collectors`.
6. Extend `_print_summary` with a `Machine state` row: `Not refreshed` when skipped, otherwise `<succeeded> succeeded, <partial> partial, <failed> failed`. Print every partial/failed collector warning in yellow after the table even without `--verbose`; continue through the ordinary backup and retain the existing exit status unless a separate existing fatal error occurs. Keep file progress events unchanged because the callback requires a real `FileEntry`, and generated snapshots naturally produce ordinary scan/upload events.
7. Update every direct `BackupEngine` construction in existing tests to pass `collect_machine_state_snapshot=False` unless that test explicitly exercises collection, update both fake engine constructor signatures in `tests/test_cli.py`, and add `--skip-machine-state` to existing CLI completion tests that instantiate the real engine. This prevents tests from invoking the host's PowerShell/WSL tools while preserving production default-on behavior. No Drive API changes or dependencies are required.
8. Update `README.md` where it describes the workflow, run flags, and configuration: state that refresh is default-on; `_machine_state` is scanned/uploaded under the Drive profile; `machine_state_collectors` controls the named collector list; outputs intentionally include unredacted environment values and may contain API keys or other secrets; `--skip-machine-state` leaves prior snapshots eligible for backup; collector failures warn and continue; every WSL distro may be started; configured scanner exclusions still win; and `--dry-run` refreshes local snapshots unless combined with the skip flag.
## Critical files & anchors
- `src/drive_backup/machine_state.py` — new typed subprocess/collector boundary and stable JSON artifact contract; no existing equivalent was found.
- `src/drive_backup/engine.py` — `BackupEngine.__init__` and `run()` between manifest load and Drive authentication; this is the single pre-scan orchestration seam.
- `src/drive_backup/config.py` — `Config`, `_STRING_LIST_FIELDS`, `_CONFIG_FIELDS`, and `_validate_config_values()` define the strict named-collector configuration contract.
- `src/drive_backup/report.py` — `BackupStats`, `BackupReport`, and `generate_report()` carry non-fatal collector outcomes to the CLI and JSON report.
- `src/drive_backup/cli.py` — `main()` owns the single skip flag/engine callsite; `_print_summary()` owns unconditional warning visibility.

## Assumptions & contingencies
- Full diagnostics are intentionally unredacted even though the output is uploaded: environment values, API keys present in those values, network addresses, task actions, service paths, usernames, serial numbers, and package sources are retained. The feature still does not discover or copy credential/config files from outside the ordinary `backup_root`; if such files are already under that root, existing backup rules apply.
- The supported runtime remains Windows PowerShell as documented. If `powershell.exe` is unavailable, each PowerShell-backed collector records `failed`, retains its prior file where available, and the ordinary backup continues; do not add a PowerShell 7 or non-Windows implementation in this change.
- WSL inspection deliberately starts every registered distro when necessary. If WSL is absent or returns no distros, write a successful `wsl.json` with `available: false` or an empty distro list respectively; if enumeration itself fails, mark only `wsl` failed and continue.
- `_machine_state` is a tool-owned directory inside `backup_root`. Disabled known-collector files may be deleted during refresh, but unknown/user-created files are never removed. If user exclusions match `_machine_state` or its JSON files, generation still occurs but the ordinary scanner exclusion wins; document that configuration rather than bypassing it.
